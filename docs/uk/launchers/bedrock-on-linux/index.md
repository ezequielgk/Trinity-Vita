# BedrockOnLinux
**Запускайте Minecraft Bedrock для Windows (видання GDK) у Linux із нативним акаунтом Microsoft/Xbox, мультиплеєром, друзями та Realms**

[Відвідати репозиторій](https://github.com/Wyze3306/BedrockOnLinux)

BedrockOnLinux встановлює вибрану вами версію Minecraft, готує керований Wine-префікс і запускає гру через перевірений рушій **GDK-Proton на основі WineGDK**. На пристрої гравця не потрібні компілятор або встановлення Windows.

## Що надає версія 2.0

- **Нативний акаунт Xbox:** конфігурація XGame, XUser, сигнатури запитів, геймертеги, привілеї та контекст XSAPI реалізовані у WineGDK.
- **Гра онлайн:** список друзів, запрошення, приєднання до друзів, публічні сервери та Realms використовують цей нативний акаунт. Realms отримує окремий XSTS-токен для аудиторії Bedrock Realms замість загального токена Xbox.
- **Без патчера пам'яті Minecraft:** керований рушій не містить коду, який сканує або переписує запущений процес Minecraft. Пакування відхиляє залишки колишньої реалізації пам'яті процесу. Статичні, перевірені за відбитками виправлення сумісності гри та Proton усе ще застосовуються перед запуском.
- **Нативний вибір файлів:** закріплений рушій реалізує засіб вибору WinAppSDK для обох архітектур Windows, а кожна підготовка зупиненого префікса відновлює його реєстрацію активації. Тому імпорт світів у грі та вибір власного скіна Minecraft відкривають діалог вибору файлів робочого столу замість помилки в `RoGetActivationFactory`. Імпорт `.mcskin` на боці лаунчера залишається доступним як додатковий неінтерактивний шлях встановлення.
- **Безпека графіки:** лаунчер перевіряє поточний стан дисплея та текстові журнали ядра без відкриття Vulkan або OpenGL. Відома небезпечна сесія блокується до запуску Wine. Графічний інтерфейс пропонує підтвердження лише для перевіреного інциденту з попереднього завантаження; він не може скасувати поточну помилку драйвера або запущену сесію Wine/UMU.
- **Перевірені оновлення:** архіви рушія, критичні файли середовища виконання та корисні навантаження залежностей прив'язані до SHA-256. Відхилене оновлення не замінює робочий рушій.
- **Ізольовані профілі акаунтів:** один користувач Linux може створити окремі корені для акаунта Xbox, Wine-префікса, налаштувань і світів, спільно використовуючи великі завантаження гри, рушія та середовища виконання.

> [!NOTE]
> Процес входу Microsoft відбувається локально між лаунчером, службами Microsoft і Xbox. BedrockOnLinux не використовує ретранслятор акаунтів або мультиплеєрний проксі.

## Встановлення

Завантажте файли застосунку з [останнього релізу](https://github.com/Wyze3306/BedrockOnLinux/releases). Усі поточно підтримувані збірки орієнтовані на Linux x86-64.

| Формат | Для кого | Команда запуску |
| --- | --- | --- |
| AppImage | Більшість дистрибутивів на основі glibc | `./BedrockOnLinux-*-x86_64.AppImage` |
| .deb | Debian, Ubuntu, Mint і LMDE | `sudo apt install ./bedrock-on-linux_*_amd64.deb` |
| Переносний .pyz | Система з Python 3.9+ та Tk | `./bedrock-on-linux-*.pyz gui` |
| Flatpak-пакет | Ізольована локальна установка, коли доступний | `flatpak install --user ./BedrockOnLinux-*-x86_64.flatpak` |

### Швидкий старт з AppImage

```sh
chmod +x BedrockOnLinux-2.1.1-x86_64.AppImage
./BedrockOnLinux-2.1.1-x86_64.AppImage
```

Для першого запуску ПОГРАТИ потрібен відповідний архів рушія:

```
GDK-Proton-xuser-<engine-revision>.tar.gz
```

За наявності інтернет-з'єднання лаунчер автоматично завантажує точний архів із релізу BedrockOnLinux. Ви також можете зберігати цей файл рушія поруч із AppImage або .pyz; відповідний локальний супутній файл має пріоритет і перевіряється перед розпакуванням. Це обов'язково під час тестування неопублікованого кандидата та корисно для офлайн-встановлення з нуля.

Існуючу установку оновлюють так само під час наступного запуску ПОГРАТИ. Лаунчер перевіряє новий рушій перед атомарною заміною та зберігає попереднє дерево, якщо завантаження, вільне місце на диску, розпакування або перевірка завершаться невдачею.

Якщо FUSE недоступний, AppImage може розпакувати себе під час запуску:

```sh
APPIMAGE_EXTRACT_AND_RUN=1 ./BedrockOnLinux-2.1.1-x86_64.AppImage
```

AppImage містить Python, Tk, графічний набір інструментів, криптографію та сертифікати CA. Він усе ще використовує графічний драйвер хоста та стандартні бібліотеки X11, Xft і fontconfig.

## Вимоги та обмеження

- **Робочий стіл на x86-64 glibc.** AppImage і керований рушій перевірені на базовому рівні glibc 2.31. Системи на ARM і лише musl, як-от стандартний Alpine, не підтримуються. Користувацький простір i386 не потрібен; керований рушій використовує чистий шлях WoW64 від Wine.
- **X11 або XWayland** для графічного інтерфейсу лаунчера. Гра зазвичай використовує X11/XWayland. Нативний Wayland від Wine можна спробувати з `BOL_INPUT=wayland`, але він залишається експериментальним ігровим бекендом.
- Робочий **драйвер Vulkan 1.3**, який підтримує `VK_EXT_device_generated_commands`, або старіший NVIDIA `VK_NV_device_generated_commands`.
- ГПУ, постійно обмежені до Vulkan 1.2, можуть спробувати **Налаштування > Додатково > Рендерер сумісності для застарілого обладнання** (WineD3D), який обходить обмеження Vulkan 1.3 від DXVK.
- Достатньо вільного місця для гри, стисненого рушія та тимчасового розпакування.
- **Акаунт Microsoft із правом доступу до Minecraft.** Друзі, мультиплеєр та Realms також залежать від налаштувань приватності акаунта та доступності служб.

> [!WARNING]
> Лаунчер є незалежним проєктом сумісності та не пов'язаний із Mojang або Microsoft і не підтримується ними.

## Гра

1. Відкрийте BedrockOnLinux.
2. Виберіть **Увійти**, відкрийте показану лаунчером сторінку коду пристрою Microsoft і введіть її код.
3. Виберіть версію Minecraft, а потім натисніть **ПОГРАТИ**.
4. Звичайно використовуйте вкладки Minecraft **Друзі**, **Сервери** та **Realms**.

Під час першого запуску завантажуються та готуються Minecraft, а потім завантажуються та перевіряються керований рушій та його корисне навантаження сумісності онлайн/TLS. Облікові дані зберігаються в приватному каталозі даних BedrockOnLinux і заносяться в зупинений Wine-префікс перед запуском.

## Кілька локальних профілів Xbox

Створіть один ізольований корінь лаунчера та ярлик на робочому столі для кожного гравця:

```sh
bedrock-on-linux profiles create "Alice"
bedrock-on-linux profiles create "Bob"
bedrock-on-linux profiles list
```

Кожен ярлик задає власний `BOL_HOME`, тому акаунт Microsoft, Wine-префікс, кеш попередньої автентифікації, налаштування та світи залишаються окремими. Пакети гри, Proton, UMU та кеші завантажень є спільними, щоб уникнути дублювання багатогігабайтних завантажень.

Оскільки команда ПОГРАТИ може відновити спільне середовище виконання перед запуском, одночасно Minecraft може працювати лише в одному профілі.

## Досягнення

Лаунчер готує окремий XSTS-токен лише для користувача для запиту оригінальних досягнень Windows у Minecraft. XUser вибирає його лише для служби досягнень, зберігаючи пакетний заголовок Windows, SCID і платформу, залишаючи автентифікацію соціальної мережі, Marketplace, PlayFab, мультиплеєра та Realms незмінною.

> [!NOTE]
> Це завантажує наявний список; він не розблоковує, не емулює та не примушує досягнення.

## Імпорт контенту

Дії Minecraft **Імпорт світу** та вибір скіна використовують нативний засіб вибору файлів WineGDK. Для прямого встановлення контенту на боці лаунчера, коли Minecraft закрито:

```sh
bedrock-on-linux import world.mcworld addon.mcaddon pack.mcpack \
  template.mctemplate skin.mcskin
```

Лаунчер імпортує архіви `.mcworld`, `.mcaddon`, `.mcpack`, `.mctemplate` та `.mcskin` у відповідний каталог `com.mojang`.

## Безпека графічного процесора

BedrockOnLinux навмисно не відкриває пристрій Vulkan або OpenGL, щоб вгадати, чи здоровий драйвер. Перед запуском він може виявити такі умови:

- сесія X11 без апаратного провайдера RandR;
- повернення до FBDEV або програмного рендерингу;
- фатальна подія графічного драйвера в журналі ядра;
- сесія ГПУ Minecraft, яка не завершилася до перезавантаження або втрати живлення.

Коли лаунчер може довести, що інцидент, який залишився, належить попередньому завантаженню, **Налаштування > Інструменти** показує **Підтвердити попередній інцидент ГПУ…** із кроком підтвердження. Еквівалентний потік CLI:

```sh
bedrock-on-linux doctor
bedrock-on-linux doctor --acknowledge-gpu-crash
```

## Діагностика та відновлення

Відкрийте **Налаштування > Відкрити папку журналів** або перегляньте:

```
$XDG_DATA_HOME/bedrock-on-linux/logs/
```

Панель «Деталі» у графічному інтерфейсі містить живий журнал лаунчера. Корисні команди:

```sh
bedrock-on-linux doctor                 # залежності хоста та безпека ГПУ
bedrock-on-linux doctor --network       # DNS/TLS, годинник і спостереження за VPN
bedrock-on-linux repair                 # перебудувати керований Wine-префікс
bedrock-on-linux versions               # доступні стабільні версії
bedrock-on-linux versions --beta        # включно з бета-версіями
bedrock-on-linux setup --mc <version>   # завантажити та підготувати одну версію
bedrock-on-linux login                  # прив'язати акаунт Microsoft
bedrock-on-linux play                   # запустити вибрану версію
bedrock-on-linux update                 # перевірити наявність оновлення лаунчера
```

## Цілісність рушія та походження вихідного коду

Керований рушій не збирається на комп'ютері користувача. Супроводжувачі релізів створюють його із закріплених вхідних даних, а лаунчер приймає лише ревізію та SHA-256 архіву, записані в `bol/config.py`.

- **WineGDK** збирається в непривілейованому chroot Debian 11 (Bullseye). Кожен отриманий ELF відхиляється, якщо він вимагає символ glibc новіший за 2.31.
- Універсальна збірка **vkd3d-proton** містить перевірені варіанти EXT-DGC і відновлені NV-DGC для x86-64 та i386.
- `scripts/package-engine.sh` вбудовує ліцензії, записи збірки, походження вихідного коду та `engine-manifest.json`, який хешує критичні файли середовища виконання.
- Встановлення рушія використовує блокування та транзакційне перейменування. Перерване або недійсне оновлення не може непомітно стати активним керованим рушієм.

## Ліцензія

BedrockOnLinux не постачає жодних файлів гри Minecraft. WineGDK, GDK-Proton, vkd3d-proton і включені залежності залишаються під їхніми відповідними ліцензіями. Сам BedrockOnLinux ліцензований за **MIT**.
