# BedrockOnLinux
**Запускайте Minecraft Bedrock для Windows (издание GDK) в Linux с нативной учётной записью Microsoft/Xbox: мультиплеер, друзья и Realms**

[Посетить репозиторий](https://github.com/Wyze3306/BedrockOnLinux)

BedrockOnLinux устанавливает выбранную вами версию Minecraft, подготавливает управляемый Wine-prefix и запускает игру через проверенный движок **GDK-Proton на основе WineGDK**. На машине игрока не требуются ни компилятор, ни установка Windows.

## Что предоставляет версия 2.0

- **Нативная учётная запись Xbox:** конфигурация XGame, XUser, подписи запросов, геймертеги, привилегии и контекст XSAPI реализуются WineGDK.
- **Игра по сети:** список друзей, приглашения, присоединение к друзьям, публичные серверы и Realms используют эту нативную учётную запись. Realms получает выделенный токен XSTS для аудитории Bedrock Realms вместо универсального токена Xbox.
- **Без патча памяти Minecraft:** управляемый движок не содержит кода, который сканирует или переписывает запущенный процесс Minecraft. Упаковка отклоняет остатки прежней реализации через память процесса. Статические идентифицируемые исправления совместимости игры и Proton по-прежнему применяются перед запуском.
- **Нативный выбор файлов:** зафиксированный движок реализует выборщик WinAppSDK для обеих архитектур Windows, и каждая подготовка остановленного префикса восстанавливает его регистрацию активации. Поэтому импорт миров и выбор пользовательских скинов в игре Minecraft открывают диалог рабочего стола вместо ошибки в `RoGetActivationFactory`. Импорт `.mcskin` на стороне лаунчера остаётся доступен как дополнительный неинтерактивный способ установки.
- **Безопасность графики:** лаунчер проверяет текущее состояние дисплея и текстовые журналы ядра, не открывая Vulkan или OpenGL. Известная небезопасная сессия блокируется до запуска Wine. Графический интерфейс предлагает подтверждение только для проверенного инцидента с прошлой загрузки; он не может отклонить текущий сбой драйвера или запущенную сессию Wine/UMU.
- **Проверенные обновления:** архивы движка, критически важные файлы среды выполнения и зависимые полезные нагрузки привязаны к SHA-256. Отклонённое обновление не заменяет рабочий движок.
- **Изолированные профили учётных записей:** один пользователь Linux может создавать отдельные корни для учётной записи Xbox, Wine-prefix, настроек и миров, совместно используя при этом большие загрузки игры, движка и среды выполнения.

> [!NOTE]
> Поток входа в Microsoft выполняется локально между лаунчером и службами Microsoft и Xbox. BedrockOnLinux не использует ретранслятор учётных записей или мультиплеерный прокси.

## Установка

Скачайте файлы приложения из [последнего релиза](https://github.com/Wyze3306/BedrockOnLinux/releases). Все поддерживаемые в настоящее время сборки предназначены для Linux x86-64.

| Формат | Для чего лучше | Команда запуска |
| --- | --- | --- |
| AppImage | Большинство дистрибутивов на базе glibc | `./BedrockOnLinux-*-x86_64.AppImage` |
| .deb | Debian, Ubuntu, Mint и LMDE | `sudo apt install ./bedrock-on-linux_*_amd64.deb` |
| Портативный .pyz | Хост с Python 3.9+ и Tk | `./bedrock-on-linux-*.pyz gui` |
| Пакет Flatpak | Изолированная локальная установка, когда доступен | `flatpak install --user ./BedrockOnLinux-*-x86_64.flatpak` |

### Быстрый старт с AppImage

```sh
chmod +x BedrockOnLinux-2.1.1-x86_64.AppImage
./BedrockOnLinux-2.1.1-x86_64.AppImage
```

Для первого запуска PLAY требуется соответствующий архив движка:

```
GDK-Proton-xuser-<engine-revision>.tar.gz
```

При наличии интернет-соединения лаунчер автоматически загружает точный архив из релиза BedrockOnLinux. Вместо этого вы можете разместить этот компонент движка рядом с AppImage или .pyz; соответствующий локальный файл предпочтителен и проверяется перед распаковкой. Это необходимо при тестировании неопубликованного кандидата и полезно для офлайн-установки с первого раза.

Существующая установка обновляется таким же образом при следующем запуске PLAY. Лаунчер проверяет новый движок перед атомарной заменой и сохраняет предыдущее дерево, если загрузка, место на диске, распаковка или проверка не удались.

Если FUSE недоступен, AppImage может извлечь себя во время выполнения:

```sh
APPIMAGE_EXTRACT_AND_RUN=1 ./BedrockOnLinux-2.1.1-x86_64.AppImage
```

AppImage включает Python, Tk, набор графических инструментов, криптографию и сертификаты CA. Он по-прежнему использует драйвер графики хоста и общие библиотеки X11, Xft и fontconfig.

## Требования и ограничения

- **Рабочий стол x86-64 с glibc.** AppImage и управляемый движок проверяются на базовой версии glibc 2.31. Системы на ARM и только с musl, такие как стандартный Alpine, не поддерживаются. Пользовательское пространство i386 на хосте не требуется; управляемый движок использует чистый путь pure-WoW64 от Wine.
- **X11 или XWayland** для графического интерфейса лаунчера. Игра обычно использует X11/XWayland. Нативный Wine Wayland можно попробовать с `BOL_INPUT=wayland`, но он остаётся экспериментальным игровым бэкендом.
- Работающий **драйвер Vulkan 1.3**, поддерживающий `VK_EXT_device_generated_commands`, или более старый NVIDIA `VK_NV_device_generated_commands`.
- Видеокарты, постоянно ограниченные Vulkan 1.2, могут попробовать **Настройки > Дополнительно > Устаревший рендерер совместимости** (WineD3D), который обходит ограничение Vulkan 1.3 в DXVK.
- Достаточно свободного места для игры, сжатого движка и временной распаковки.
- **Учётная запись Microsoft с правом на Minecraft.** Друзья, мультиплеер и Realms также зависят от настроек конфиденциальности учётной записи и доступности сервисов.

> [!WARNING]
> Лаунчер — это независимый проект совместимости, не связанный с Mojang или Microsoft и не поддерживаемый ими.

## Игра

1. Откройте BedrockOnLinux.
2. Выберите **Войти**, откройте показанную лаунчером страницу с кодом устройства Microsoft и введите её код.
3. Выберите версию Minecraft, затем нажмите **PLAY**.
4. Обычным образом используйте вкладки Minecraft **Друзья**, **Серверы** и **Realms**.

При первом запуске загружается и подготавливается Minecraft, затем загружается и проверяется управляемый движок и его полезная нагрузка совместимости для сети/TLS. Учётные данные хранятся в приватном каталоге данных BedrockOnLinux и помещаются в остановленный Wine-prefix перед запуском.

## Несколько локальных профилей Xbox

Создайте изолированный корневой каталог лаунчера и ярлык рабочего стола для каждого игрока:

```sh
bedrock-on-linux profiles create "Alice"
bedrock-on-linux profiles create "Bob"
bedrock-on-linux profiles list
```

Каждый ярлык задаёт собственный `BOL_HOME`, поэтому учётная запись Microsoft, Wine-prefix, кэш предварительной авторизации, настройки и миры остаются раздельными. Пакеты игры, Proton, UMU и кэши загрузок являются общими, чтобы избежать дублирующих загрузок размером в гигабайты.

Поскольку PLAY может восстановить общую среду выполнения перед запуском, одновременно запускать Minecraft может только один профиль.

## Достижения

Лаунчер подготавливает выделенный токен XSTS только для пользователя для исходного запроса Windows-достижений Minecraft. XUser выбирает его только для сервиса достижений, сохраняя упакованный заголовок Windows, SCID и платформу, при этом аутентификация для социальных функций, Marketplace, PlayFab, мультиплеера и Realms остаётся без изменений.

> [!NOTE]
> Это загружает существующий список; это не разблокирует, не эмулирует и не принуждает достижения.

## Импорт контента

Действия Minecraft **Импорт мира** и выбор скинов используют нативный выборщик файлов WineGDK. Для прямой установки контента на стороне лаунчера, пока Minecraft закрыт:

```sh
bedrock-on-linux import world.mcworld addon.mcaddon pack.mcpack \
  template.mctemplate skin.mcskin
```

Лаунчер импортирует архивы `.mcworld`, `.mcaddon`, `.mcpack`, `.mctemplate` и `.mcskin` в соответствующий каталог `com.mojang`.

## Безопасность графики

BedrockOnLinux намеренно не открывает устройство Vulkan или OpenGL, чтобы угадать, исправен ли драйвер. Перед запуском он может обнаружить такие условия, как:

- сеанс X11 без аппаратного провайдера RandR;
- откат на FBDEV или программный рендеринг;
- фатальное событие драйвера графики в журнале ядра;
- сессия GPU Minecraft, не завершившаяся до перезагрузки или потери питания.

Когда лаунчер может доказать, что оставшийся инцидент относится к предыдущей загрузке, **Настройки > Инструменты** отображают **Подтвердить предыдущий инцидент GPU…** с шагом подтверждения. Эквивалентный процесс через CLI:

```sh
bedrock-on-linux doctor
bedrock-on-linux doctor --acknowledge-gpu-crash
```

## Диагностика и восстановление

Откройте **Настройки > Открыть папку журналов** или проверьте:

```
$XDG_DATA_HOME/bedrock-on-linux/logs/
```

Панель «Подробности» в графическом интерфейсе содержит актуальный журнал лаунчера. Полезные команды:

```sh
bedrock-on-linux doctor                 # зависимости хоста и безопасность GPU
bedrock-on-linux doctor --network       # наблюдения DNS/TLS, часов и VPN
bedrock-on-linux repair                 # пересоздать управляемый Wine-prefix
bedrock-on-linux versions               # доступные стабильные версии
bedrock-on-linux versions --beta        # включая бета-версии
bedrock-on-linux setup --mc <version>   # скачать и подготовить одну версию
bedrock-on-linux login                  # привязать учётную запись Microsoft
bedrock-on-linux play                   # запустить выбранную версию
bedrock-on-linux update                 # проверить обновление лаунчера
```

## Целостность движка и происхождение исходного кода

Управляемый движок не собирается на компьютере пользователя. Сопровождающие релизов создают его из зафиксированных входных данных, и лаунчер принимает только ревизию и SHA-256 архива, записанные в `bol/config.py`.

- **WineGDK** собирается в непривилегированной chroot-среде Debian 11 (Bullseye). Каждый полученный ELF отклоняется, если он требует символ glibc новее 2.31.
- Универсальная сборка **vkd3d-proton** содержит проверенные варианты EXT-DGC и восстановленные варианты NV-DGC для x86-64 и i386.
- `scripts/package-engine.sh` включает лицензии, записи сборки, происхождение исходного кода и `engine-manifest.json`, который хэширует критически важные файлы среды выполнения.
- Установка движка использует блокировку и транзакционное переименование. Прерванное или недействительное обновление не может незаметно стать активным управляемым движком.

## Лицензия

BedrockOnLinux не поставляет файлы игры Minecraft. WineGDK, GDK-Proton, vkd3d-proton и входящие в комплект зависимости остаются под их соответствующими лицензиями. Сам BedrockOnLinux распространяется по **лицензии MIT**.
